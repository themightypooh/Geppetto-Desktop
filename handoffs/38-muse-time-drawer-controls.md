# Muse — rework the TIMELINE drawer's TIME page for run controls

**Status: design handoff, not authorization to change production UI yet.** Po is iterating on the portable prototype at `artifacts/geppetto-cabinet-controls-standalone.html`. Wait for an explicit go-ahead before implementing. The user chose the existing bottom drawer labelled TIMELINE with a **three-position physical switch: BUILD / CLIP / KEYS**. BUILD gets run controls, CLIP retains the current TIME playback controls, and KEYS retains the dope sheet. Do not add a RUN CONTROLS lid button or big viewport overlays. Do not start/restart the shared chest or use paid models for design verification.

## 1. Establish the real baseline before editing

1. Read `cabinet/cabinet.qml` lines around the `Drawer` component, `timeline`, `tlFloor`, `timePage`, `keyPage`, and `pageSwitch`. Read `cabinet/art/geom.js`. The baked drawer is 1006×254 px; its floor is 864×168; the viewport is 1024×576 and four panes are about 511×287. Preserve the cabinet's native-pixel geometry and open/close behaviour.
2. TIME currently contains **clip playback** transport, LCD, steel frame ruler, BONES/GRID/SOLID/FRAME and clip tapes. KEYS has its own dope sheet, editing keys and ruler. The existing TIME/KEYS slider is a black physical switch at drawer-local x=16, y=44, width=38, height=120. Do not treat the drawer as empty or silently drop clip playback without an explicit product decision about where it goes.
3. The prototype's **Current QML** and KEYS pages are actual offscreen captures of `cabinet.qml`, not reconstructed drawings: `artifacts/timeline-qml-time.png` and `artifacts/timeline-qml-keys.png`. The **Reworked** page is a proposal using the baked `drawer_timeline.png`, `key.png`, `key_down.png`, `lamp_on.png`, `lamp_off.png`, and `rule.png`. Compare them at **Inspect drawer · 100%**, not just the scaled Fit view.
4. Existing per-run protocol supports pause, resume, one-change `step`, exact pace 0–30 seconds, and cancel. `Host.stepRun`, `Host.setPace`, and `Host.stopResearch` exist in `cabinet/host.py`; a public QML-callable Pause/Resume slot in Host is **not present in the current source**. Side-pane `spKeys` and `ReplayStrip` are `visible: false`; `RunPaceSlider.qml` exists but isn't instantiated in the cabinet. Do not claim a working visible per-pane control surface from these helpers.

## 2. Match the agreed mockup, not the abandoned alternatives

1. Give the drawer three distinct pages: **BUILD** (pane-targeted run station), **CLIP** (the existing TIME transport/ruler/view switches/clip tapes, behaviour preserved), and **KEYS** (the existing dope sheet, behaviour preserved). Keep the drawer label TIMELINE. Replace its two-position TIME/KEYS slider with a three-position physical switch, not a stack of generic buttons. The third detent, labels, knob travel and click/drag/keyboard hit targets must fit in the side-wall space without overlapping the drawer floor.
2. Inside the exposed drawer floor, use the existing 84×36 baked `Key` component for four pane selectors and the run actions. Selected pane and held/replay states use amber lamps, while STOP has a distinct danger treatment. The first row is pane 1–4 selection plus a status LCD with selected pane, run state and revision. The second row is **PAUSE/RESUME, STEP −, STEP +, STOP, REPLAY/LIVE, and build pace**. STEP − and STEP + are separate adjacent keys. Disable unavailable actions visibly, but keep their labels readable.
3. Replace the mockup's generic bottom range slider with the **actual QML ruler language**: tile `art/rule.png` at 24 px height, draw narrow minor and longer major steel ticks, number major steps, show an amber progress/burnt-in segment, and use the red cursor with a red numbered flag. The currently selected saved build revision determines the flag position. Hit geometry, ticks, numbers and flag must share one step-to-x mapping, including the first and last endpoints. Clicking/dragging the ruler selects a saved step; keyboard arrows/Home/End should work when focused.
4. Keep this rule a **build-step/replay ruler**, not the old clip-frame ruler. Name its range from the actual saved steps, not from guessed sequential revisions: `live_runs.steps(directory)` supplies steps and `Pane.replay` supplies the `count`, `at`, `rev`, and `shown` state. Some revisions can be nonconsecutive. Use indices for spacing and display the real revision/step label. The mockup uses sequential fake values only as a visual sample.
5. The drawer does not get an extra RUN CONTROLS key in the cabinet lid. Keep pane surfaces minimal at quad size. Do not move these controls into a floating panel or cover a viewport with the rule.

## 3. Route the selected pane safely

1. Resolve the selected pane through `root.activePane` and the pane's actual run directory at the moment of the command. Pane 1 and panes 2–4 have different existing replay objects/methods (`host` versus `host.paneList[n-2]`); share UI logic without silently retargeting a command when focus or the watched run changes. Never fall back from an empty pane to another running pane.
2. Add a narrowly scoped Host Pause/Resume QML slot that sends the existing validated `pause` or `resume` command **to that exact run**. Pause holds after the current operation; Resume only follows an explicit user action. `STEP +` uses `Host.stepRun(runDir)` when that run is held, advances exactly one change and holds again. `STOP` uses `Host.stopResearch(runDir)` for the selected run only; don't call `claudeStopAll`.
3. `RunPaceSlider.qml` already handles external state updates, 0–30 second clamping, delayed submit and run identity changes. Reuse its protocol/guard behaviour in the drawer-sized pace presentation; never send a pending pace edit to a different run when selection changes. The slider's current native orientation maps Slow-left / Fast-right while the HTML mock displays seconds; resolve the displayed direction/label before implementation so the value and words agree.
4. `REPLAY` opens the selected pane's saved run, the ruler seeks it without modifying the live run, and `LIVE` returns to its newest model. Replay starts/stops explicitly; selecting a historical step must not resume a held build.
5. **STEP − is not yet an existing inverse of `step`.** The mock simulates moving backward, but production policy is still open. Safe default for implementation planning: move the *replay cursor* one saved step back without mutating the run; do not silently call `rewind_run` or decrement a real revision. The existing `replayRewind`/`Host.rewind_run` path is an explicit **REWIND HERE** operation for open runs and changes the saved model. Ask po whether STEP − should only inspect or actually rewind before wiring any destructive behaviour. If this is unresolved, leave STEP − in the production design unimplemented/disabled with a clear reason rather than inventing a command.
6. Keep notes/corrections in their same-run workflow. No correction, replay seek, chat-window event, pane selection or quality check should implicitly resume a held run.

## 4. Verify before deployment

1. Add offscreen QML tests that open TIMELINE, switch **BUILD↔CLIP↔KEYS** (all three positions), select panes 1–4, and assert exact run-directory routing for Pause/Resume, STEP +, STOP and pace. Verify the existing clip PLAY/LOOP/frame scrub and KEYS controls still work after the switch change. Test empty, stopped and changed-run states. Verify STEP − according to the policy po approves, including a case that proves inspecting history does not mutate the live run.
2. Check the ruler's first/last endpoints, sparse/nonconsecutive steps, no steps, one step, seeking while a revision loads, and repaint after a new step arrives. Check keyboard, drag and click. Ensure the flag and tooltip never leave the drawer and long names wrap or elide with a full hover tip.
3. Render the actual shared QML offscreen at minimum/default/maximum UI scales and at 1/2/4 panes; inspect screenshots for clipping, overlap, drawer handle accessibility, and the KEYS page still functioning. The existing four-real-viewport pace test in `tests/test_run_pace_slider.py` currently fails with missing controls; make its assertions fit the newly selected **drawer** surface rather than pretending four sliders live in viewport headers, and do not suppress unrelated failures.
4. Run focused CPU/QML control tests and report exact commands, exit codes and screenshots. Do not mark production verified from the HTML mockup, compilation alone, or a helper not called from `cabinet.qml`. Do not open or restart the shared chest unless po explicitly requests live deployment.
