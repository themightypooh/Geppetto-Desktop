## Goal and non-negotiable behavior

1. Agent reads the relevant Effigy API/toolset and makes a short subject-specific tool/material plan **before** filing an intent. Script is complete and preflighted before the toast; after Yes there is no research or script rewrite. Use Profile/Spline/Blob/brush/sculpt/UV/bake/material features when appropriate, not default flat-colour box/cylinder piles. A checker cannot certify taste; verify real tool invocation and a saved revision, then review the model visually with po.
2. Filing an intent reserves exactly one of four panes. Try requested pane, then following numbers, wrapping 4→1. Never evict another model, a static model, a replay, a user edit, or another reservation. All four occupied → **refuse immediately**. Multiple agents may have independent pending intents in distinct panes; no global “one pending” lock. The displayed card/toast names the **assigned** pane and exact subject/worker.
3. No script starts before Yes. No → release reservation, no runner. Yes → cabinet starts the exact approved script **without waiting for the agent's next SSH/tool turn**. Target: first visible geometry in its assigned viewport within five seconds of the click under the supported test fixture; record click, launch, run registration and first-frame timestamps separately. Do not claim this from token-write or `Popen` latency alone. If startup fails or misses deadline, show an explicit failure and terminate **only that intent's run**; do not silently queue or launch into a different pane.
4. The worker's existing `geppetto-live … --gate-token ID` call must attach/wait on the **same** run and produce its Build receipt, not start a second model. Waits are bounded, ownership is tied to intent/session and exact script hash/path, and duplicates never consume another lane's receipt. Existing `more|skip|rewind|close` on the same run are not fresh intents. New run/new subject requires new Yes.
5. If the chest is closed, intent filing fails immediately. Closing it cancels pending/unused approvals, unblocks local waiters, stops cabinet-owned provider turns and runs, and leaves no orphan spending tokens. Do **not** kill unrelated SSH shells, external CLI sessions, or another app's processes. An external Muse worker must see a cancellation record promptly; cooperative remote cancellation has limits and must be stated honestly.
6. No provider-specific quality/speed settings. The Muse bridge is a transport exception, not a different modeling policy. No silent retry or second paid turn. Keep every agent in its own run/pane/workspace and do not alter another pane while testing.
