## 3. Canonical source and sync policy

### 3.1 Shared kernel files (376 same + 38 differing)

- **Canonical: Desktop `kernel/Effigy/`.** Mobile
  `vendor/geppetto-desktop/kernel/Effigy/` is a synced mirror. No hand
  edits in `vendor/`; a vendor file changes only by a ticketed sync from
  Desktop, or by porting a Mobile-side addition back through its ticket.
- **No blind overwrite of either side.** A sync is per-file, ticket-scoped,
  and must preserve both sides' public APIs (see §4). Overwriting
  Desktop with Mobile loses Desktop-only APIs; overwriting Mobile with
  Desktop loses Mobile-only APIs (103 extractor-flagged Mobile-only
  declarations across 21 files, §5).
- **Implementation-only drift (17 files)** — bytes differ, public API
  identical: `FaceDelete.cs`, `Features/SlotLook.cs`,
  `Features/StudioDocument.cs`, `Implicit.cs`, `Measure.cs`,
  `MeshAdjacency.cs`, `MeshNormals.cs`, `Multires.cs`,
  `PaintReplay.cs`, `PaintTextureSet.cs`, `Plugins/PluginManager.cs`,
  `Rig/RigAnimWriter.cs`, `Rig/SkinWeights.cs`,
  `Rig/WeightPaintSession.cs`, `Script/BuildScript.RefTools.cs`,
  `TexelStroke.cs`, `UVLayoutCheck.cs`. These sync by behaviour review
  only; no API design is needed. `StudioDocument.cs` is AS01-owned
  (serializer, §6) and converges under AS01, not under a separate ticket.
- **API-additive drift (21 files)** — Mobile adds public API Desktop
  lacks, or (one case) Desktop adds API Mobile lacks. Each file moves
  only through its named ticket (§7). A sync that drops a Mobile-only
  declaration to "match Desktop" is a regression, not a sync.
- **The outer kernel is out of scope.** Desktop's kernel is a vendored
  copy that already diverges from `../geppetto/Effigy/`
  (`VmdlReader.cs` precedent, BOARD.md). Syncing with the outer tree is a
  separate coordinator decision. Never edit `../geppetto/Editor/Effigy`
  (generated mirror, RULES.md rule 8).

### 3.3 Desktop `core/` and Mobile `app/`

Each is canonical for itself; there is no cross-sync between them.
They consume the kernel only through a project reference:

- Desktop `core/Geppetto.Core.csproj` → `../kernel/Effigy.Kernel.csproj`.
- Mobile `app/GeppettoMobile.csproj` → `../vendor/geppetto-desktop/kernel/Effigy.Kernel.csproj`.

A core/app file never duplicates kernel logic to work around drift; the
fix belongs in the kernel ticket. `core/` has no Mobile counterpart and
`app/` has no Desktop counterpart; do not invent one.

### 3.4 Project files

`kernel/Effigy.Kernel.csproj` globs `Effigy/**/*.cs`, is `Deterministic`,
and pins `InformationalVersion` (`1.0.0+4af78c2…`) because the value is
baked into the assembly's `ModuleVersionId`, the `StudioCache` key
(changing it invalidates every cache entry). Do not change the glob, the
pin, or `Deterministic` as part of a parity sync. The Desktop and Mobile
vendor copies of `Effigy.Kernel.csproj` are byte-identical at snapshot
time — the project files have not drifted, only the sources under them.
Both this csproj and `core/Geppetto.Core.csproj` carry a provenance
comment pointing at this contract; that comment is the only change this
ticket makes to them.

survive every sync in either direction:

  — `kernel/Effigy/MeshBoolean.cs:77`. Present in Desktop, absent from

  that ticket must keep `ApplyParallel` working, not merely keep the
  file compiling.

Two extractor-flagged "Desktop-only" entries were **verified equivalent
and are not preservation items** — do not re-file them:

- `PaintCanvas.cs`: Desktop declares
  `public PaintCanvas RoughnessMap, MetalnessMap, HeightMap;` in one
  line; Mobile declares the same three fields plus `EmissiveMap,
  OpacityMap, NormalMap` in one line. Same API, different grouping.
- `PaintLayers.cs`: Desktop declares
  `public PaintCanvas Color, Roughness, Metalness, Height;`; Mobile
  declares the same four plus `Emissive, Opacity, Normal`. Same API,
  different grouping.

(The extractor renders a multi-declarator field line as one combined
signature, so grouping differences look like API differences. Verify by
grep before asserting any API gap. The generator's member regex was
fixed for the same reason: an expression-bodied member's body used to
be swallowed into its parameter list.)

## 6. Shared serializer ownership

**AS01 is the serializer owner.** Hub task
`support-mobile-assembly-documents-without-losing-occurrences`
(playtester-21) is the sole writer of:

- `kernel/Effigy/Assembly/AssemblyDocument.cs` (new, ported),
- `kernel/Effigy/Features/PartStudio.cs` (assembly field only),
- `kernel/Effigy/Features/StudioDocument.cs` (format-3 `assemblyjson`
  line + legacy v1/v2 only).

No second writer to `StudioDocument`; all later serializer changes
coordinate through AS01. Downstream assembly work is already split into
AS02–AS15 (`assemblies-02` … `assemblies-15`); the cancelled
`expose-assembly-placement-joints-motion-and-posed-export` task is
superseded by AS06 (`assemblies-06`), which owns
`kernel/Effigy/Assembly/AssemblySolver.cs`. This contract creates no
competing serializer owner and no second `StudioDocument` writer.

Known serializer boundary found by AS01: Desktop has no
`AssemblyMateFeature` (Mobile-only); Mobile documents carrying a mate
feature are refused by name, never silently dropped. A mate-feature port
is a separate ticket, not part of AS01.

Known namespace hazard found by AS01: the new `Effigy.Assembly`
namespace shadows `System.Reflection.Assembly` in kernel files; any
kernel file that opens the namespace must fully qualify
`System.Reflection.Assembly` (AS01 fixed `FeatureRegistry.cs:23` and
`PluginManager.cs:25` this way, matching Mobile). Future ports that add
an `Assembly/` type must apply the same qualification.

## 7. Native adapters

The kernel itself is engine-free C#; native capability arrives through
adapters owned by their own tickets, not through kernel P/Invokes.
(Verified: no `DllImport` in either kernel tree at snapshot time —
re-check with `grep -rn DllImport kernel/Effigy` when this contract is
next revised.)

| Adapter | Source | Owning ticket |
|---|---|---|
| Manifold boolean backend (portable, honest fallback) | Mobile-side boolean implementation; Desktop keeps `MeshBoolean.ApplyParallel` as the parallel path | `integrate-portable-manifold-boolean-backend-with-honest-fallback` |
| OpenVDB remesh + Instant Meshes retopo backends | External remesh/retopo backends, integrated behind `RemeshFeature` | `integrate-openvdb-remesh-and-instant-meshes-retopo-backends` |
| XAtlas unwrap (`UVUnwrap.XAtlas.cs`) | Mobile vendor kernel file; xatlas-based unwrap behind `UVUnwrap` | `preserve-manual-uv-island-edits-and-improve-automatic-unwrap` |

No adapter is vendored into the kernel by this ticket. A ticket that
introduces a native dependency must name its source, version, and
license, and must keep the kernel building without it where the ticket
says "honest fallback".

## 8. Drift detection (the gate)

```sh
cd /home/poo/Desktop/geppetto-desktop
python3 tools/kernel-parity/inventory.py check \
    --baseline handoffs/kernel-parity-inventory.json
```

Exit 0: no drift (meta excluded). Exit 1: prints every added, removed,
or changed file with its API delta. Run it before and after any sync;
a sync that changes a kernel file must regenerate the baseline in the
same change (`generate --out handoffs/kernel-parity-inventory.json`)
and hand the updated baseline to the coordinator with the change — never
edit the JSON by hand.

`tests/KernelParityTests.cs` (new, this ticket) is the in-suite form of
the same gate: it re-hashes the Desktop trees against the committed
baseline and asserts `MeshBoolean.ApplyParallel` exists by reflection.
It is **not yet registered** in `tests/TestRegistry.cs` — that file is
coordinator-owned (BOARD.md); the final integrator adds the one
`KernelParityTests.Register(registry, settings);` line. Until then the
script above is the gate.

## 9. Extractor limits (read before disputing a count)

- Source-level regex, not Roslyn: a declaration split across lines, a
  multi-declarator field line, or an exotic generic signature can render
  differently from the same API on the other side. Counts are a drift
  signal; a claimed API gap must be confirmed by grep (as §4 was).
- Only `public`/`protected` type and member declarations are extracted.
  `internal` members, explicit interface implementations, and local
  functions are not part of the API surface.
- Comments and string literals are stripped before extraction, so a
  `public` inside a comment or string never counts.
- Hash equality is the API guarantee for the 376 identical files: same
  bytes means same API, no extraction needed.

## 10. What this ticket does not do

- No kernel file is synced, ported, or overwritten by this ticket.
- No UI, no viewer launch, no full project build (PO workflow override
  2026-11-13). Checks run are the inventory generator (twice,
  deterministic), the `check` gate, and a targeted `csc` compile of the
  new test file against the prebuilt kernel DLL (see §11). Full suites
  are deferred to the final integrator.
- No new serialization format, no change to `.effigy`/`.riganim`
  handling, no change to the pinned `InformationalVersion` or the
  `Effigy/**/*.cs` glob.
